## 1. 압축 포맷 선정 (2026-08-31)

**결과: 7z `-mx=5` 채택**

프로젝트 하나(`음원+악보병합 프로젝트`)로 실측:

| 방식 | 크기 | zip 대비 | 압축 시간 |
|---|---|---|---|
| zip (`tar -a`) | 829.2 MB | — | 47.6초 |
| 7z `-mx=1` | 745.6 MB | **−10.1%** | **22.6초** |
| 7z `-mx=5` | 656.9 MB | **−20.8%** | 73.5초 |

`-mx=1` 이 zip 보다 **작으면서 두 배 빠릅니다.** Windows 내장 `tar` 의 deflate 는 단일
스레드이고 7-Zip 은 `-mmt` 로 모든 코어를 쓰기 때문입니다. zip 을 유지할 이유가 없습니다.

**전체 실측** — `-mx=5` 로 6.30 GB → **4,741,108,614 B (4.74 GB / 4.42 GiB)**.
프로젝트 하나로 예측한 −21% 와 일치합니다.

**결과: 통과.** 가장 중요한 확인입니다.

```powershell
978
```

`.git` 디렉터리 13개가 `.git_archived` 로 변환되어 **978개 파일이 실제로 추적**되고 있습니다.

## 8. 스크립트만 갱신하고 작업 정의를 두었을 때 (2026-08-31)

**결과: 사고 직전에 발견**

트리거는 스케줄러가 XML 로 들고 있습니다. `ts_backup.bat` 을 덮어써도 **바뀌지 않습니다.**
설계가 순환(매시간·프로젝트 하나)에서 전체 스냅샷(하루 1회·6 GB)으로 바뀌었는데도
작업은 옛 정의를 유지하고 있었습니다.

| | 옛 정의 | 새 정의 |
|---|---|---|
| 트리거 | 매시간 + 로그온 + 절전 해제 (3종) | 매일 04:00 (1종) |
| 한 회차 | 프로젝트 1개, 수십~수백 MB | 전체 6.3 GB, 20분 안팎 |

두 쪽을 섞으면 하루 종일 회차가 이어집니다. `MultipleInstancesPolicy=IgnoreNew` 는
겹침만 막을 뿐 빈도를 줄이지 않습니다.

**교훈: 스크립트를 배포할 때마다 트리거를 눈으로 확인할 것.** 절차는
[install.md 6단계](../scripts/install.md#6단계--작업-스케줄러-등록) 에 넣었습니다.

```cmd
powershell -NoProfile -Command "(Get-ScheduledTask -TaskName 'TailscaleProjectBackup').Triggers | Format-List"
```

`Repetition` 이 있거나 트리거가 둘 이상이면 낡은 정의입니다.

## 검증 과정에서 발견해 수정한 결함

### 배포 전 코드 리뷰에서 잡은 것

| 결함 | 증상 |
|---|---|
| `if <조건> A & B` | `B` 가 조건과 무관하게 항상 실행 → **롤백 2~4순위가 완전히 죽음** |
| `echo %VAR% > file` | 값 뒤 공백 기록 → 비교 영구 실패 |
| `tar -C <경로> *` | `*` 가 현재 디렉터리 기준으로 해석될 위험 |
| robocopy 종료 코드 | 성공 시에도 1~7 반환. `equ 0` 판정은 오판 |
| `-xr!이름` | 지연 확장이 `!` 를 먹어 **제외가 조용히 무시됨**. 목록 파일 방식으로 대체 |

### 실제 실행 중 드러난 것

| 커밋 | 결함 | 증상 |
|---|---|---|
| `ea5bd94` | 로그 메시지의 `>` 가 리디렉션으로 승격 | `sent x -> host` 한 줄이 로그가 아니라 `host` 라는 이름의 파일로 빠져나감 |
| `37d6ed0` | `%USERDOMAIN%` 이 `WORKGROUP` 반환 | `schtasks` 등록 시 SID 매핑 실패 |
| `8e86d69` | `findstr /i "Last"` | 한글 Windows 에서 매칭 실패. **잘못된 값을 못 잡고 지나침** |
| `d46053a` | `$env:USERPROFILE` 로 경로 유도 | 계정이 둘인 환경에서 엉뚱한 프로필을 보고 **`no archives to ingest` 로 조용히 성공 종료** |
| `27aae56` | `Mandatory [string[]]` | 빈 문자열이 든 배열 바인딩 거부 → 크래시 |
| `27aae56` | 인코딩 | 로그가 깨져 나왔고, 같은 방식으로 쓰던 `.ts_state.json` 은 한글 프로젝트명이 왕복에서 깨져 **카운터가 매 실행 초기화될 뻔함** |
| `dea8b8e` | `git commit` 출력 전량 기록 | 32,000줄이 한 회차에 기록되어 로그 회전 기준을 즉시 초과 |

마지막 두 건은 **겉으로 아무 이상 없이 잘못 동작할 뻔한** 유형입니다. 로그가 깨진 덕에
인코딩 문제가 드러났고, 그 과정에서 상태 파일 쪽의 더 심각한 문제가 함께 잡혔습니다.

### 관리 화면 코드 리뷰에서 잡은 것

실행 없이 읽어서만 잡은 것들이라, 이 목록이 결함이 없다는 뜻은 아닙니다.

| 결함 | 증상 |
|---|---|
| `$ErrorActionPreference = 'Stop'` + 네이티브 `2>&1` | Windows PowerShell 은 리디렉션된 stderr 한 줄을 `ErrorRecord` 로 바꾸고, `Stop` 아래에서는 그것이 **종료 오류**가 됩니다. `R`(즉시 실행)로 `schtasks` 가 실패하면 그 메시지를 보여 주는 대신 **화면 전체가 죽습니다.** 받는 쪽에서 이미 같은 문제를 겪어 `Invoke-Native` 로 해결했는데, 관리 화면에는 그 방어가 빠져 있었습니다 |
| `[Console]::KeyAvailable` / `ReadKey` | 표준 입력이 리디렉션된 세션(`ssh host "powershell -File ..."`)에서 **예외**를 던집니다. 이 시스템은 SSH 로만 관리하므로 실제로 밟기 쉬운 경로였습니다. 시작할 때 한 번 탐지해 자동으로 1회 출력 모드로 내려갑니다 |
| `SetCursorPosition(0, 0)` | 좌표 기준이 창이 아니라 **화면 버퍼**입니다. 프레임이 창보다 길어 한 번이라도 스크롤되면 0행은 보이지 않는 위쪽이라 화면이 멈춘 것처럼 보입니다. `[Console]::WindowTop` 으로 바꾸고, 프레임을 창 높이로 잘라 애초에 스크롤이 나지 않게 했습니다 |
| `Test-Path -LiteralPath $null` | `CONFIG` 블록을 정규식으로 못 읽으면 값이 `$null` 이 되고, `Stop` 아래에서 바인딩 오류로 죽습니다. 배포된 스크립트가 문서보다 낡았을 때 정확히 이 상황이 됩니다 |
| `$width += if (...) {...}` | 문법상 유효하지만 확인할 방법이 없어 평범한 `if` 문으로 바꿨습니다 |

증상별 대처는 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) 를 참고하십시오.

## 1. 압축 포맷 선정 (2026-08-31)

**결과: 7z `-mx=5` 채택**

프로젝트 하나(`음원+악보병합 프로젝트`)로 실측:

| 방식 | 크기 | zip 대비 | 압축 시간 |
|---|---|---|---|
| zip (`tar -a`) | 829.2 MB | — | 47.6초 |
| 7z `-mx=1` | 745.6 MB | **−10.1%** | **22.6초** |
| 7z `-mx=5` | 656.9 MB | **−20.8%** | 73.5초 |

`-mx=1` 이 zip 보다 **작으면서 두 배 빠릅니다.** Windows 내장 `tar` 의 deflate 는 단일
스레드이고 7-Zip 은 `-mmt` 로 모든 코어를 쓰기 때문입니다. zip 을 유지할 이유가 없습니다.

**전체 실측** — `-mx=5` 로 6.30 GB → **4,741,108,614 B (4.74 GB / 4.42 GiB)**.
프로젝트 하나로 예측한 −21% 와 일치합니다.

## 8. 스크립트만 갱신하고 작업 정의를 두었을 때 (2026-08-31)

**결과: 사고 직전에 발견**

트리거는 스케줄러가 XML 로 들고 있습니다. `ts_backup.bat` 을 덮어써도 **바뀌지 않습니다.**
설계가 순환(매시간·프로젝트 하나)에서 전체 스냅샷(하루 1회·6 GB)으로 바뀌었는데도
작업은 옛 정의를 유지하고 있었습니다.

| | 옛 정의 | 새 정의 |
|---|---|---|
| 트리거 | 매시간 + 로그온 + 절전 해제 (3종) | 매일 04:00 (1종) |
| 한 회차 | 프로젝트 1개, 수십~수백 MB | 전체 6.3 GB, 15분 |

두 쪽을 섞으면 하루 종일 회차가 이어집니다. `MultipleInstancesPolicy=IgnoreNew` 는
겹침만 막을 뿐 빈도를 줄이지 않습니다.

**교훈: 스크립트를 배포할 때마다 트리거를 눈으로 확인할 것.** 절차는
[install.md 6단계](../scripts/install.md#6단계--작업-스케줄러-등록) 에 넣었습니다.

```cmd
powershell -NoProfile -Command "(Get-ScheduledTask -TaskName 'TailscaleProjectBackup').Triggers | Format-List"
```

`Repetition` 이 있거나 트리거가 둘 이상이면 낡은 정의입니다.

## 10. 두 PC 의 날짜가 하루 다름

**결과: 미해결. 실사용에 영향 있음**

```
보내는 쪽 로그    2026-08-31 18:07:37   전송 완료
받는 쪽 파일      2026-09-01 18:07      PycharmProjects_2026_08_31_17_52.7z
```

시각(시·분)은 같고 **날짜만 하루 차이**입니다. 3절의 로그에서도 같은 어긋남이
보입니다 — 받는 쪽이 `2026-09-01 13:56` 에 처리한 압축의 이름이
`PycharmProjects_2026_08_31_13_27` 입니다. 며칠째 이 상태였습니다.

압축 파일 이름의 타임스탬프는 **보내는 쪽 시계**에서 나오고, 받는 쪽은 그것을 그대로
**git 태그**로 씁니다. 따라서 복원 지점의 이름이 실제 날짜와 하루 어긋납니다. 데이터가
손상되지는 않지만 "언제 것인지"를 태그로 판단할 수 없게 됩니다.

**어느 쪽이 틀렸는지부터 확인하십시오.** 양쪽에서:

```cmd
powershell -NoProfile -Command "Get-Date -Format 'yyyy-MM-dd HH:mm:ss zzz'"
```

이 환경에서는 받는 PC 가 `2026-09-01 18:53:54 +09:00` 으로 정확했고 **보내는 PC 가 하루
뒤처져 있었습니다.** 시차가 아니라 날짜 오차입니다 — 표준 시간대가 달랐다면 시(hour)가
어긋났을 텐데 분까지 같고 날짜만 다릅니다.

```cmd
w32tm /query /status
w32tm /resync
```

`w32tm /resync` 와 시간 변경에는 **관리자 권한이 필요합니다.** 비관리자 SSH 세션에서는
거부되므로, 그 경우 본체에서 설정 → 시간 및 언어 → "지금 동기화" 로 맞춰야 합니다.

## 12. 관리 콘솔 — 인증·권한 (2026-09-09)

**결과: 통과 (자동 검사). 실기 SSH 접속은 미검증**

이 항목들은 **테스트가 실제 서버를 띄우고 붙어서** 확인합니다. 표에 그렇게 적혀 있는
것과 엔드포인트가 실제로 막는 것은 다른 문제이고, 후자만이 의미가 있습니다.

| 확인한 것 | 방법 | 결과 |
|---|---|---|
| 로그인 전 모든 경로 차단 | 실제 요청 11개 | `/healthz`·`/login` 만 열림 |
| **WebSocket 터미널 차단** | 실제 서버 + 실제 WS 연결 | 쿠키 없이 거부 |
| 쿠키 위조 | 빈 값·쓰레기·서명 없음·변조·만료 | 전부 거부 |
| 무차별 대입 | 연속 실패 7회 | 429 잠금 |
| 역할별 경계 | admin/operator/viewer/미등록/익명 × 4개 동작 | 표대로 |
| **viewer 의 터미널** | 실제 WS 연결 | admin 만 열림 |
| 신원 헤더 위조 | 공개 바인딩에서 `Tailscale-User-Login` | 무시됨 |
| 잘못된 권한 표 | `"adminn"`, `default: "root"` | 로딩 거부 |

**WebSocket 을 따로 검사하는 이유**가 있습니다. `@app.middleware("http")` 는
WebSocket 스코프를 보지 못합니다. 그 사실을 모르면 **화면은 잠기고 셸만 열려 있는**
상태가 됩니다 — 이 프로젝트에서 실제로 그럴 뻔했습니다.

PowerShell 을 보내고 있었으므로, **강제 명령이 "받은 base64 실행"이면 제한이
장식**입니다. 프로토콜을 동사 기반으로 바꾼 뒤에야 검증할 것이 생깁니다.

| 확인한 것 | 결과 |
|---|---|
| 동사 문법 — 허용 | `whoami`, `status`, `log 1~500`, `task run\|enable\|disable` |
| 동사 문법 — 거부 | **주입 시도 19가지** (`;` `&&` `\|` 개행 `$()` 백틱 대소문자 인자추가 빈값) |

| 작업 이름 | **전송되지 않음** (가드가 보유) |
| 가드 본문 | 파일로 실행될 때만 자기 호출 (`$PSCommandPath`) |

### 2026-09-12 후속 — 실기에서 터진 크래시, 그리고 인스톨러

**PyInstaller 빌드 자체는 이후 CI(`desktop-release.yml`)에서 여러 차례 실제로
성공했습니다** — 위 목록의 "PyInstaller 빌드" 항목은 이제 검증됨으로 갱신합니다.
다만 그 과정에서 헤드리스 코어 테스트로는 잡히지 않는 실기 전용 결함이 두 건
나왔고, 사용자가 실제로 배포된 `.exe` 를 실행하면서 세 번째가 나왔습니다:

| 결함 | 어디서 안 잡혔나 | 고침 |
|---|---|---|
| Windows 콘솔이 cp1252 라 한글 `print()` 가 `UnicodeEncodeError` | 이 리눅스 샌드박스는 UTF-8 이라 재현 안 됨 — 실제 Windows 러너에서 CI 가 처음 잡음 | `sys.stdout/stderr.reconfigure(encoding="utf-8")` + CI 에 `PYTHONUTF8`/`PYTHONIOENCODING` |
| `console=False` 빌드는 `sys.stdout` 이 `None` — 인코딩과 무관하게 `print()` 가 무조건 크래시 | 위와 같은 이유로 CI 가 잡음(코드 리뷰 중 발견, 실행 전에) | 콘솔 유무를 `is not None` 으로 가드, 상태는 항상 로그 파일로 |
| 프로즌 엔트리 스크립트(`app/main.py`)의 상대 임포트(`from .main_window import ...`) — PyInstaller 부트로더는 이 파일을 진짜 `__main__` 으로 실행해 부모 패키지가 없음(`python -m app.main` 과 다름) | **CI 스모크 테스트가 `--config` 만 돌려서 놓침** — `_gui()` 까지 안 가고 리턴함. **실제 사용자가 배포된 `.exe` 를 켜고서야** `ImportError: attempted relative import with no known parent package` 로 드러남 | 절대 임포트(`from app.main_window import ...`)로 교체. 같은 부류의 재발을 잡도록 `--check-gui` (창은 안 띄우고 그 임포트만 검사) 추가, CI 스모크 테스트에 편입 |

이 세 번째 것이 중요한 이유: **오프스크린 Qt 임포트 테스트(§15 본문의
"GUI 배선은 오프스크린 Qt 로... 확인")는 `app.main_window`/`app.tray` 를 평범한
모듈 임포트로 불러왔지, `app/main.py` 자체를 프로즌 엔트리 스크립트로 실행한 게
아니었습니다.** 그래서 "임포트가 되는가"는 확인했지만 "프로즌 상태의 `main.py`
자신의 임포트문이 유효한가"는 놓쳤습니다. 로컬에서 `python app/main.py`(⚠️
`-m` 없이 직접 실행 — 정확히 같은 `__main__`/부모 패키지 없음 조건)로 재현·수정
확인 후, 같은 방법으로 이전 코드가 정확히 같은 오류를 내는 것도 재확인했습니다.

**인스톨러 추가** — `.exe` 를 그냥 배포하는 대신 Inno Setup 으로 감싸
`TsBackup-Setup.exe` 를 만듭니다(`desktop/build/tsbackup.iss`). CI 가 이제
검증하는 것: 인스톨러가 실제로 컴파일되는지, `/CURRENTUSER` 로 조용히 설치한
뒤 **설치된 경로**(`%LOCALAPPDATA%\Programs\TsBackup\TsBackup.exe`)에서
`--config`/`--check-gui` 가 통과하는지.

| 커밋 | 결함 | 증상 |

| `704a757` | **WebSocket 이 인증을 우회** | `@app.middleware("http")` 는 WebSocket 스코프를 보지 못합니다. 모르고 넘어갔다면 **화면은 잠기고 셸만 열려 있는** 상태가 됐을 것입니다 |

다시 읽어서** 나왔습니다 — 특히 `AutoAddPolicy` 는 바로 앞 커밋에서 추가한 Render

### 관리 화면 코드 리뷰에서 잡은 것

실행 없이 읽어서만 잡은 것들이라, 이 목록이 결함이 없다는 뜻은 아닙니다.

| 결함 | 증상 |
|---|---|
| `$ErrorActionPreference = 'Stop'` + 네이티브 `2>&1` | Windows PowerShell 은 리디렉션된 stderr 한 줄을 `ErrorRecord` 로 바꾸고, `Stop` 아래에서는 그것이 **종료 오류**가 됩니다. `R`(즉시 실행)로 `schtasks` 가 실패하면 그 메시지를 보여 주는 대신 **화면 전체가 죽습니다.** 받는 쪽에서 이미 같은 문제를 겪어 `Invoke-Native` 로 해결했는데, 관리 화면에는 그 방어가 빠져 있었습니다 |
| `[Console]::KeyAvailable` / `ReadKey` | 표준 입력이 리디렉션된 세션(`ssh host "powershell -File ..."`)에서 **예외**를 던집니다. 이 시스템은 SSH 로만 관리하므로 실제로 밟기 쉬운 경로였습니다. 시작할 때 한 번 탐지해 자동으로 1회 출력 모드로 내려갑니다 |
| `SetCursorPosition(0, 0)` | 좌표 기준이 창이 아니라 **화면 버퍼**입니다. 프레임이 창보다 길어 한 번이라도 스크롤되면 0행은 보이지 않는 위쪽이라 화면이 멈춘 것처럼 보입니다. `[Console]::WindowTop` 으로 바꾸고, 프레임을 창 높이로 잘라 애초에 스크롤이 나지 않게 했습니다 |
| `Test-Path -LiteralPath $null` | `CONFIG` 블록을 정규식으로 못 읽으면 값이 `$null` 이 되고, `Stop` 아래에서 바인딩 오류로 죽습니다. 배포된 스크립트가 문서보다 낡았을 때 정확히 이 상황이 됩니다 |
| `$width += if (...) {...}` | 문법상 유효하지만 확인할 방법이 없어 평범한 `if` 문으로 바꿨습니다 |

증상별 대처는 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) 를 참고하십시오.

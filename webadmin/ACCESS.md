# 접근 권한 관리

> 외부 인증 서비스(Auth0, Google 로그인, Okta …) 없이, 우리가 직접 관리하는 방안.

---

## 결론

**Tailscale 이 "누구인가"를 답하고, `access.json` 이 "무엇을 할 수 있는가"를 답합니다.**

```
                    누구인가                무엇을 할 수 있는가
브라우저 ──▶ tailscaled (whois) ──▶ access.json ──▶ 콘솔
             암호학적으로 확인          우리가 소유
```

새로 도입하는 서비스가 하나도 없습니다. tailnet 은 이미 돌고 있고, 권한 표는
저장소 안의 파일 하나입니다.

---

## 왜 이 조합인가

### 신원은 Tailscale 이 이미 알고 있습니다

`tailscaled` 는 WireGuard 세션에서 **연결마다 어느 tailnet 사용자인지 이미 알고**
있습니다. 콘솔은 물어보기만 하면 됩니다.

```
tailscale whois --json 100.101.7.4:54321
```

이게 직접 로그인을 만드는 것보다 나은 이유:

| | 자체 로그인 | Tailscale 신원 |
|---|---|---|
| 저장하는 비밀 | 비밀번호 해시, 세션, 재설정 토큰 | **없음** |
| 사람 한 명 회수 | 계정 삭제 + 세션 무효화 | admin 콘솔에서 기기 제거 — **이미 하는 일** |
| 피싱 | 가능 | 불가능. 신원이 터널에서 나옵니다 |
| 관리할 목록 | 사용자 DB + tailnet | **tailnet 하나** |

마지막 줄이 실무에서 제일 큽니다. **목록이 두 개면 반드시 어긋납니다.** 퇴사자를
tailnet 에서는 지웠는데 콘솔 계정은 남아 있는 상황이 전형적인 사고입니다.

### 권한은 Tailscale 이 답할 수 없습니다

ACL 은 "이 기기가 저 포트에 닿는가"까지입니다. **"이 사람이 백업 기기의 셸을 열어도
되는가"는 이 콘솔에 대한 질문**이지 네트워크에 대한 질문이 아닙니다. 그래서 권한 표는
여기, 강제하는 코드 옆에 둡니다.

파일인 이유도 있습니다 — **읽고, diff 하고, PR 에서 리뷰할 수 있습니다.** 아무도 안을
들여다볼 수 없는 DB 보다 낫습니다.

## 4단계

```json
{
  "default": "none",
  "users": {
    "you@example.com":      "admin",
    "teammate@example.com": "operator",
    "readonly@example.com": "viewer"
  }
}
```

| 단계 | 할 수 있는 것 |
|---|---|
| `none` | 아무것도. **목록에 없는 사람의 기본값** |
| `viewer` | 읽기 — 대시보드, 상태, 로그 |
| `operator` | + 즉시 실행, 스케줄 일시중지/재개 |
| `admin` | + **터미널**, 연결 설정 편집, 감사 로그 |

### 터미널이 admin 인 것이 이 표의 핵심입니다

다른 권한은 전부 **범위가 정해진 동작**입니다. 셸은 아닙니다. 셸이 있으면
백업 스크립트를 고치고, 스케줄을 끄고, **이 프로젝트가 지키려는 바로 그 `.env` 를 읽고**,
스냅샷을 지울 수 있습니다.

> **터미널을 주는 것은 admin 을 주는 것보다 작은 결정이 아닙니다. 같은 결정입니다.**

연결 설정 편집도 admin 인 이유가 한 단계 건너 같습니다 — 호스트 주소를 자기 기기로
바꾸면 그다음엔 터미널이 거기로 붙습니다.

`default` 를 `none` 이 아닌 값으로 두지 마십시오. tailnet 에 새 기기가 들어오면 그
사람이 자동으로 그 권한을 갖게 됩니다.

## 켜는 법

```cmd
set TSCONSOLE_AUTH=tailscale
copy access.example.json access.json
:: access.json 을 실제 로그인 이름으로 고친 뒤
python -m app.main --ssh --host 100.101.7.4
```

로그인 이름은 `tailscale status` 에 나옵니다.

시작할 때 두 가지를 확인하고, 안 맞으면 **뜨지 않습니다.**

- `tailscale` 명령이 없으면 → 모든 요청이 신원 미확인이 되어 콘솔이 무용지물이므로 거부
- 권한 표가 비어 있으면 → 아무도 아무것도 못 하므로 거부

## 반드시 알아야 할 함정 하나

`tailscale serve` 는 `Tailscale-User-Login` 헤더를 넣어 줍니다. 편하지만
**그 포트에 tailscaled 말고 아무도 못 닿을 때만** 믿을 수 있습니다.

```bash
curl -H "Tailscale-User-Login: boss@example.com" http://그주소:8765/
```

공개 주소에 바인딩한 채 헤더를 믿으면 이 한 줄이 전체 권한 체계입니다.
**이것이 신원 헤더 프록시가 뚫리는 표준적인 방법입니다.**

그래서 코드가 이렇게 합니다.

| 바인딩 | 헤더 | whois |
|---|---|---|
| `127.0.0.1` (뒤에 `tailscale serve`) | **신뢰** | 신뢰 |
| `100.x` 또는 `0.0.0.0` | **무시** | 신뢰 |

`whois` 는 클라이언트가 보내는 것이 아니라 **실제 TCP 상대 주소**를 tailscaled 에게
물어보는 것이라 위조할 수 없습니다.

## 감사 로그

권한 관리에서 빠뜨리기 쉬운 절반입니다. **"세 사람만 셸을 열 수 있다"보다
"14일 03시에 누가 열었나"가 실제로 받는 질문입니다.**

`audit.log`, JSONL, 한 줄에 한 사건.

```json
{"at":"2026-09-09T03:12:44+0900","event":"terminal.open","who":"you@example.com","level":"admin","client":"100.72.55.18","host":"sender"}
{"at":"2026-09-09T03:14:02+0900","event":"denied","who":"readonly@example.com","level":"viewer","method":"POST","path":"/api/hosts/sender/action","required":"operator"}
```

기록하는 것: 로그인, 거부, 즉시 실행/일시중지, 터미널 열기·닫기, 연결 설정 저장.
**조회는 기록하지 않습니다** — 10초마다 도는 대시보드 폴링이 한 달에 여섯 줄뿐인
중요한 기록을 파묻습니다.

`/api/audit` 는 admin 전용입니다. 누가 무엇을 했는지가 그 자체로 보호 대상입니다.

## 겹쳐 쌓기

한 겹으로 끝내지 마십시오. 순서대로 값이 큽니다.

**1. 네트워크 — tailnet 밖에 내놓지 않기.** 제일 싸고 제일 셉니다.
공개 주소가 없으면 인증을 뚫을 기회 자체가 없습니다.

**2. ACL — 콘솔 노드가 닿는 곳을 좁히기.**

```jsonc
{
  "tagOwners": { "tag:ts-control": ["autogroup:admin"] },
  "acls": [{
    "action": "accept",
    "src": ["tag:ts-control"],
    "dst": ["desktop-nb8bfur:22", "wisenesco-23031302:22"]
  }]
}
```

콘솔이 털려도 tailnet 전체가 아니라 **그 두 포트만** 노출됩니다.

**3. 신원 + 역할** — 이 문서.

**4. 감사** — 무슨 일이 있었는지.

## 다른 선택지와 비교

| 방안 | 외부 서비스 | 사람별 구분 | 즉시 회수 | 이 프로젝트에서 |
|---|---|---|---|---|
| **Tailscale 신원 + 역할 표** | 없음¹ | O | O | **권장** |
| 공유 비밀번호 하나 | 없음 | X | 전원 변경 | 혼자 쓸 때는 충분 |
| mTLS (자체 CA) | 없음 | O | CRL 관리 필요 | tailnet 을 못 쓸 때의 차선 |
| 사용자 DB + 해시 | 없음 | O | O | 직접 IdP 를 운영하게 됨 |
| Google/Auth0 로그인 | **있음** | O | O | 요구사항 위반 |

¹ Tailscale 조정 서버는 이미 이 프로젝트의 전제입니다. **새로** 들이는 외부 서비스가
없다는 뜻입니다. 그것마저 피해야 한다면 mTLS 로 가되, 인증서 발급·폐기·갱신을
직접 운영해야 한다는 점을 감안하십시오 — 대부분 그 부담이 얻는 것보다 큽니다.

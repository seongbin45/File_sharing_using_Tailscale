# TS Backup (PyQt 데스크톱 앱)

디렉터리를 통째로 **7z 로 압축**하고, 압축 파일을 **날짜·시간으로 넘버링**하며,
**정해진 간격마다** 이전 압축을 지우고 새로 압축해 상대 PC 로 **계속 보내는** 데스크톱
프로그램입니다. 보내는 쪽과 받는 쪽을 **하나의 .exe** 로 쓰지만, 역할은 첫 실행 때
한 번 고르는 갈림길입니다 — 실수로 바꿀 수 있게 화면에 토글로 두지 않고,
바꾸려면 설정에서 한 단계 들어갑니다(아래 "설치와 실행", "화면" 참고).

기존 배치/PowerShell + Tailscale 시스템과 **같은 명명 규칙**(`<폴더>_YYYY_MM_DD_HH_MM.7z`)을
쓰므로, 받는 쪽의 타임스탬프-태그 관리와 그대로 이어집니다.

> 이 앱은 붙여주신 "파일 경로 목록을 스트리밍" 하던 코드와 다릅니다. 그 방식은 파일의
> **내용이 아니라 경로 텍스트**만 보냈고, `0.0.0.0` 공개 바인딩 등 위험이 있었습니다.
> 여기서는 **디렉터리를 실제로 압축**해 바이너리로 보냅니다.

## 무엇을 하는가

**보내는 쪽 (sender)**
1. 트리거(N시간마다)가 오면 `대상 폴더` 하위를 **전부** 7z(LZMA2)로 압축
   — `.env`, `.git` 포함, 제외 없음
2. 파일명은 `<폴더이름>_2026_09_11_04_00.7z`
3. 압축 전에 **이전 압축을 삭제**(`로컬 보관 개수`만 남김) — "지우고 새로 압축"
4. 선택한 전송 방식으로 보냄. 실패하면 fallback 순서로 재시도
5. 전부 실패하면 압축 파일을 **보관**했다가 다음 트리거에서 다시 시도

**받는 쪽 (receiver)**
1. `수신 폴더` 를 5초마다 확인
2. 새 `.7z` 가 **다 도착한 뒤**(크기가 안정된 뒤) `압축 해제 폴더`의
   `PycharmProjects_<타임스탬프>/` 로 풂
3. 성공하면 원본 `.7z` 삭제(선택)

## 전송 방식

기존 Tailscale 을 기본으로 두고, OpenSSH·HTTP 를 옵션으로 붙였습니다.

| 방식 | 어떻게 | 받는 쪽 준비 |
|---|---|---|
| **taildrop** (기본) | `tailscale file cp <파일> <기기>:` | Taildrop 수신 폴더를 `수신 폴더`로 지정 |
| **sftp** | OpenSSH 로 원격 폴더에 업로드(임시명 → 완료 후 rename) | 그 폴더를 `수신 폴더`로 지정 |
| **http** | 받는 쪽 앱이 여는 서버로 청크 업로드 | 앱이 HTTP 수신 서버를 띄움(토큰 필수) |

`전송 방식` 하나 + `fallback` 여러 개를 둘 수 있습니다. 배치 버전의 `TARGETS` 순차
시도와 같은 개념을 전송 방식 전체로 넓힌 것입니다.

**보안 메모**
- **sftp**: 호스트 키 지문을 pin 합니다 — 처음 연결할 때 받은 지문을 자동으로
  등록하고(trust on first use), 이후 연결에서 그 값과 다르면 거부합니다. 짝
  코드로 설정한 경우 받는 쪽의 지문을 미리 받아 오므로 이 자동 등록 단계 자체가
  생략됩니다. 비밀번호는 파일이 아니라 환경변수 `TSBACKUP_SFTP_PASSWORD` 로
  줍니다.
- **http**: 토큰 없는 업로드는 거부합니다. 수신 바인딩 기본값은 `127.0.0.1` 이고,
  `0.0.0.0` 은 로그에 경고를 남깁니다. tailnet 안에서만 쓰십시오.

## 설치와 실행

릴리스의 `TsBackup-Setup.exe` 를 받아 실행합니다.

- **누구를 위해 설치할지** 화면에서 고릅니다 — *나만* (관리자 권한 불필요) 또는
  *이 컴퓨터의 모든 사용자* (Program Files, UAC 필요). 둘 중 하나를 고르면 됩니다.
- **Windows 시작 시 자동 실행** 체크박스는 기본으로 켜져 있습니다. 이게 켜져
  있으면 로그인할 때 트레이로 떠서 계속 상주하고, 앱 안의 자체 타이머가 예약된
  시각마다 알아서 백업을 돕니다 — 작업 스케줄러 등록이 따로 필요 없습니다.
- 설치가 끝나면 **첫 실행 마법사**가 뜹니다: 이 컴퓨터가 보내는 쪽인지 받는
  쪽인지 고르고 → 받는 쪽이 화면에 뜬 **짝 코드**(9자, 15분 후 만료·한 번 쓰면
  소멸)를 보내는 쪽에 입력하면 기기 이름·주소·전송 방식·호스트 키 지문이 자동
  으로 채워지고 → 마지막으로 작은 파일 하나를 실제로 보내고 받는 쪽이 풀었는지
  까지 확인하는 **시험 전송**을 거쳐야 끝납니다. 폴더 경로나 호스트 키를 손으로
  옮겨 적다 생기는 오타·불일치가 이 과정에서 원천적으로 없어집니다. 나중에
  기기를 더 추가하려면 받는 쪽 홈 화면의 "짝 코드 만들기"로 새 코드를 만들면
  됩니다 — 마법사를 처음부터 다시 돌릴 필요 없습니다.
- 제거는 시작 메뉴의 "Uninstall TsBackup" 또는 Windows 설정의 앱 목록에서.
  설정 파일(`%LOCALAPPDATA%\TsBackup\config.json`)은 제거해도 남습니다 —
  다시 설치하면 이전 설정 그대로 이어집니다.

소스로 실행하려면:

```cmd
cd desktop
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m app.main
```

무인 실행(작업 스케줄러)용 헤드리스 모드도 여전히 있습니다 — 트레이 상주 대신
Task Scheduler 로 직접 돌리고 싶을 때 씁니다:

```cmd
TsBackup.exe --run     :: 보내는 쪽: 한 번 압축·전송 후 종료
TsBackup.exe --scan    :: 받는 쪽: 수신 폴더 한 번 처리 후 종료
TsBackup.exe --config  :: 설정 파일 경로 출력
```

설정은 설치 방식(나만/모든 사용자)과 무관하게 항상
`%LOCALAPPDATA%\TsBackup\config.json` 에 저장됩니다(.exe 옆이 아님 —
Program Files 는 일반 계정이 못 씁니다).

## 화면

평소에 열어 보는 이유는 대개 "지금 괜찮은가" 하나라, 창의 절반을 로그로 채우는
대신 그 질문에 바로 답하는 상태 카드를 위에 두고 로그는 접어 둡니다.

- **상태 카드** — 잘 되고 있는지, 마지막 전송이 언제·얼마나 걸렸는지, 다음 전송은
  언제인지. 실패 중에는 재시도 상황(`재시도 1/3`)이 여기 나타납니다.
- **보내는 쪽 화면** — 보내는 폴더·주기, 받는 쪽 정보.
- **받는 쪽 화면** — 보관 개수·쓴 공간·짝지어진 보내는 쪽 수, 받은 파일 목록,
  그리고 **침묵 감지 배너** — 어느 보내는 쪽이든 자기 주기보다 한참 늦으면
  ("laptop-x 에서 3일째 오지 않습니다") 알려 줍니다. 보내는 쪽이 꺼져 있으면
  아무 일도 일어나지 않고, 아무 일도 없는 것은 화면에 나타나지 않으므로 이
  판정은 받는 쪽만 할 수 있습니다.
- **시작 / 일시중지 / 지금 실행(또는 지금 확인) / 설정**
- **자세한 기록** — 접힌 로그. 펼치면 시각별 기록이 보이고, 파일에도 남습니다
  (`%LOCALAPPDATA%\TsBackup\tsbackup.log`).
- **트레이 최소화** — 창을 닫아도 종료되지 않고 트레이로 내려가 **백업은 계속 실행**됩니다.
  트레이 아이콘의 점 색이 상태(대기/실행/일시중지/**실패**)를 보여 줍니다. 완전히
  끄려면 트레이 메뉴나 파일 → 종료.
- **실패 알림** — 성공은 조용히 지나가고, 실패만 트레이 알림으로 말을 겁니다.
  전송이 실패하면 20분 간격으로 3번까지 자동으로 다시 시도한 뒤에도 안 되면
  그때 한 번 알리고(재시도 도중에는 알리지 않습니다), 다음 정해진 주기로
  돌아갑니다 — 새벽에 실패한 백업이 저녁까지 조용히 방치되지 않습니다.
- **역할 바꾸기** — 화면의 토글이 아니라 파일 메뉴 → "역할 바꾸기"(설정 열기와
  동일) 한 단계 안쪽으로 옮겼습니다. 실수로 바뀌지 않게 하기 위해서입니다.

## 빌드 · 릴리스

`.exe` 는 **Windows 에서** 만들어야 합니다(PyInstaller 산출물은 OS 별). 자동 릴리스는
`vX.Y.Z` 태그를 푸시하면 GitHub Actions 의 Windows 러너가 빌드해 릴리스에 첨부합니다.
로컬 빌드와 세부는 [build/BUILD.md](build/BUILD.md).

## 검증

```cmd
cd desktop
python -m tests.selftest
```

압축·명명·보관(지우고 새로 압축)·전송 선택·fallback·수신 압축 해제·재시도/백오프
결정·짝 코드 인코딩과 교환·침묵 감지·호스트 키 지문을 **실제로 돌려서** 확인합니다
(Qt·네트워크 없이 - 짝 코드의 HTTP 왕복도 실제 소켓으로 검증하되 Tailscale 인터페이스
대신 loopback 을 씁니다). 무엇이 검증됐고 무엇이 아닌지는
[../docs/VERIFICATION.md](../docs/VERIFICATION.md) 15절.
